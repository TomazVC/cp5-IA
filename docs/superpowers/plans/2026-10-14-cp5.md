# CP5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** implementar, executar e documentar fine-tuning local de chamados na GPU.
**Architecture:** scripts Python na raiz compartilham dados/contrato em support.py e execução do modelo em model_runtime.py. train.py salva adaptadores; evaluate.py salva respostas/métricas; experiments.py escolhe configuração na validação; app.py usa o mesmo runtime.
**Tech Stack:** Python 3.12, PyTorch CUDA, Transformers, PEFT, Gradio, unittest.
**Spec:** docs/superpowers/specs/2026-10-14-cp5-design.md

## Global Constraints

- Tudo dentro de cp5; Python global preservado; sem chamadas OpenAI.
- Modelo Qwen2.5-0.5B-Instruct com LoRA; CUDA obrigatório para operações do modelo.
- 400 chamados, 250/75/75, cinco categorias, famílias separadas; teste final congelado.
- Três épocas; rank 8, alpha 16, dropout .05; batch 1, acumulação 8, 256 tokens; seed 42.
- Três learning rates: 5e-5, 1e-4, 2e-4; geração greedy/.3/.7; top_p .9.
- Loss somente na resposta; sem truncamento silencioso; resultados inválidos são erros.
- Avaliação humana pelo usuário; GitHub depende do destino informado.

## Review Focus

- JSON malformado, rótulo desconhecido e ação vazia não podem inflar métricas.
- Famílias/paráfrases entre conjuntos devem provocar falha de validação.
- Prompt longo deve ser rejeitado, sem truncamento invisível.
- Checkpoint incompleto ou GPU indisponível devem dar erro claro.
- Não escolher checkpoint/parâmetros usando teste final nem inventar avaliação humana.
